## Принятое решение

| сценарий | метод | порог |
|---|---|---|
| 1. идентичные | TF-IDF символы (n-граммы 2-4) + проверка процента и количества | 0,71 (match), зона ручной проверки 0,61-0,71 |
| 2. аналоги | TF-IDF символы | нет |
| 3. поиск | TF-IDF символы | нет |

Семантический вариант сохранён как `config_hybrid.json` (порог пар 0,84).

## Типичные ошибки

- TF-IDF по словам не находит запросы с опечатками и другими формами слов («тварог», «яйца» вместо «яйцо»).
- TF-IDF по символам ошибается на описательных запросах: «молочко» находит шоколад молочный, «что-нибудь к чаю» находит чай, «средство для стирки» находит средства для стёкол, «перекус» находит товары с похожими буквами, «свежее мясо» находит свежие овощи.
- Текстовая похожесть почти не учитывает числа и бренд: «наполнитель 4,5 кг» принимался за «наполнитель 5 кг». Это исправляет проверка признаков.
- Пары, отличающиеся вариантом товара (сорт, вкус), без проверки признаков остаются самой трудной группой для семантических моделей (e5: 7 ошибок из 80 трудных пар). Разбор конкретных пар вписать из ячейки разбора ошибок.

## Ограничения

- Положительные пары для сценария 1 получены искусственным шумом (перестановка слов, сокращения, единицы, опечатки). На реальных данных качество будет ниже.
- Отложенная часть мала: 200 товаров, 80 трудных пар, 46 товаров с аналогами, 6 трудных запросов в test. Различия в несколько процентов недостоверны.
- Разметка лексических запросов построена на совпадении слов и заранее выгодна текстовому поиску; разметка трудных запросов построена по типу и категории товара.
- Аналоги размечены правилом (тот же тип, процент, количество ±30%, другой бренд), метрики сценария 2 показывают согласие с этим правилом.
- Проверка признаков использует только процент и количество.
- В каталоге есть неточности (например, расхождение количества у одного сыра, суффиксы «(доп.)» в типах).
