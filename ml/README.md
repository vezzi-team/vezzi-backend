# smartcart_ml: ML-модуль «Умная корзина»

Три сценария:

1. **Идентичные товары** (`match`, `pair_scores`): предварительное сопоставление товаров из чужого каталога с нашим.
2. **Аналоги** (`analogs`): взаимозаменяемые товары по названию.
3. **Поиск** (`search`): товары по текстовому запросу.

## Установка

```bash
pip install -e ".[dev]"          # TF-IDF (конфигурация по умолчанию) и тесты
pip install -e ".[semantic,dev]" # дополнительно семантическая модель (config_hybrid.json)
```

Конфигурация по умолчанию не требует нейросети. При первом запуске с `config_hybrid.json` модель скачивается из интернета.

## Использование

```python
import pandas as pd
from smartcart_ml import Matcher

catalog = pd.DataFrame({"product_id": [1, 2], "name": ["Молоко Простоквашино 2,5%, 930 мл", "Кефир 1%, 900 мл"]})
m = Matcher(catalog)                                   # config.json из пакета: TF-IDF
# m = Matcher(catalog, "smartcart_ml/config_hybrid.json")       # TF-IDF + нейросеть (экспериментально)

m.match([{"id": "x1", "name": "молоко простоквашино 2.5% 0,93л"}])
m.analogs(1, top_k=5)
m.search("молочко", top_k=10)
```

## Контракт

**Каталог** (вход конструктора): таблица с колонками `product_id` (уникальный, число или строка) и `name` (непустая строка).

### `match(items, top_k=3)`
Вход: `items` - непустой список `{"id": любой JSON-скаляр, "name": непустая строка}`.
Выход: список в том же порядке:
```json
{"id": "x1", "name": "...", "decision": "match | review | no_match",
 "candidates": [{"product_id": 1, "name": "...", "score": 0.93}]}
```
`decision`: `match` - оценка лучшего кандидата не ниже порога; `review` - в пределах `review_margin` ниже порога (нужна ручная проверка); `no_match` - иначе.

### `analogs(product_id, top_k=5, candidate_ids=None)`
Выход: `[{"product_id", "name", "score"}]` по убыванию `score`, сам товар не включается. `candidate_ids` ограничивает пул кандидатов (нужен для тестов).

### `search(query, top_k=10)`
Выход: `[{"product_id", "name", "score"}]` по убыванию `score`.

### Ошибки
Пустое название, пустой запрос, пустой список, неизвестный `product_id`, дубли `product_id` в каталоге, неверный метод в конфиге: `ValueError`.

## Конфигурация (`config.json`)

| ключ | значение |
|---|---|
| `version`, `data_version` | версии конфигурации и контрольных выборок |
| `model` | имя модели эмбеддингов и префиксы для запросов и документов (нужны моделям e5) |
| `identical.method` | `tfidf`, `semantic` или `hybrid` (среднее двух оценок) |
| `identical.threshold` | порог решения. **Подбирается на train выборок v1, обновляйте при смене модели или метода.** По умолчанию 0,71 (TF-IDF), для гибрида 0,84 |
| `identical.review_margin` | ширина зоны ручной проверки под порогом |
| `identical.use_attribute_check` | отвергать пары с разным процентом или количеством |
| `analogs.method` | `tfidf`, `semantic`, `hybrid` |
| `search.method` | `tfidf`, `semantic`, `rrf` (слияние мест двух методов) |

Файлы: `config.json` (по умолчанию, TF-IDF + проверка признаков) и `config_hybrid.json` (TF-IDF + e5). Почему выбран TF-IDF, см. `EVALUATION.md`.

## Тесты

```bash
pytest -rs                                                    # config.json (TF-IDF)
SMARTCART_CONFIG=smartcart_ml/config_hybrid.json pytest -rs   # гибрид, нужна модель
```

Контрольные выборки лежат в `data/v1` (каталог, разбиение, пары, аналоги, запросы, `meta.json`); тесты ищут их в `data/v1` рядом с `pyproject.toml` или на уровень выше, либо по пути из переменной `SMARTCART_DATA`. Если выборок нет, тесты падают с понятным сообщением, а не пропускаются. Тесты проверяют контракт и нижние границы качества на отложенной части.

## Ограничения

- Контрольные пары для сценария 1 получены искусственным шумом (перестановка слов, сокращения, единицы, опечатки). На реальных данных качество может быть ниже.
- Отложенная часть мала (200 товаров, 6 трудных запросов, 46 товаров с аналогами): разницу методов в пределах нескольких процентов нельзя считать значимой.
- Разметка запросов вида `lexical` построена на совпадении слов и заранее выгодна текстовому поиску.
- Проверка признаков использует только процент и количество; отличия варианта товара (сорт, вкус) она не видит.
- Каталог загружается в память целиком, эмбеддинги считаются при создании `Matcher`.
